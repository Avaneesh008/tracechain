## 4. Implementation Decisions for P1 (SPEC Sections 4.1 & 4.2)

Recorded by P1 data preparation pipeline:

### Decision 1: Deduplication of Feature Rows
- `wallets_features.csv` contains 347,569 exact duplicate rows where `(address, Time step)` repeats with identical values.
- **Rule**: Deduplicate `wallets_features.csv` on `subset=['address', 'Time step']`, retaining the first occurrence. This yields exactly 920,691 distinct address-timestep observation rows.

### Decision 2: Address String to Integer Index Mapping
- Address IDs are Base58/Bech32 strings.
- **Rule**: Map all 822,942 unique addresses deterministically to integer indices `0` through `822,941` using lexicographical sorting (`build_address_mapping`).
- Artifacts saved under `artifacts/`:
  - `artifacts/address_to_idx.joblib`: Python dictionary mapping address string to integer node index.
  - `artifacts/idx_to_address.joblib`: 1D NumPy object array mapping integer index back to address string.

### Decision 3: Sparse Graph Construction
- **Rule**: Construct the graph using `scipy.sparse.csr_matrix` with shape `(822942, 822942)` and `float32` binary edge weights (1.0).
- Directed edges are formed from `(input_address -> output_address)`.
- Self-loops (45,981 rows) are retained in the master directed graph but zeroed out when computing undirected mean neighbor degree.
- Master graph saved under `artifacts/address_graph.npz`.

### Decision 4: Graph Feature Formulations
- **In-Degree & Out-Degree**: Column sum and row sum of the directed CSR matrix respectively.
- **PageRank**: Custom sparse power iteration with damping factor $\alpha = 0.85$, maximum iterations = 50, and uniform teleportation. Dangling nodes (out-degree = 0) redistribute mass uniformly across all nodes.
- **Mean Neighbor Degree**: Computed on the undirected graph $(A + A^T)$ with diagonal (self-loops) zeroed. For each node, sums the total degrees of its neighbors and divides by the neighbor count. Isolated nodes (0 neighbors) receive 0.0.
- Saved under `artifacts/graph_features.parquet`.

### Decision 5: Temporal Split and Leakage Partitioning
- **Train Split**: All labelled rows (`label` in `{0, 1}`) with `Time step` in `[1, 34]`.
- **Test Split**: All labelled rows (`label` in `{0, 1}`) with `Time step` in `[35, 49]`.
- **Leakage Partition**:
  - Addresses appearing in `train_df` are tracked as known/seen.
  - Test rows are partitioned into `test_df` (all test rows) and `cold_test_df` (test rows for addresses never seen in the training period).
- **Serving Rule**: `/api/score/{address}` selects the address's latest row (highest `Time step`).
- Splits saved under `artifacts/train.parquet`, `artifacts/test.parquet`, and `artifacts/cold_test.parquet`.
